# Сборка статической демо-версии

`demo/` — статическая копия сайта eStables с условным контентом; GitHub Pages публикует её как есть (`.github/workflows/pages.yml`). Страницы не пишутся руками: их рендерит сам движок из отдельной чистой установки, а затем ссылки переделываются под плоские HTML-файлы. Здесь лежит то, что нужно, чтобы повторить это на новой версии движка.

- `estables-demo.sql` — дамп базы, из которой отрендерена текущая демо-версия (схема версии 16). Пароль всех трёх администраторов в ней — `demo-password-2026`. Данные выдуманные; сессии, хеши паролей и журнал в дампе тоже условные.
- Фото в базе ссылаются на файлы по хешу. Сами файлы — в `demo/media/originals/`: это и есть оригиналы (JPEG-заглушки с силуэтом лошади), отдельно они не хранятся.

## Что в демо-версии

- Публичная часть, как её видит гость: каталог, все видимые разделы (и их фильтры по десятилетиям), все предметы, «О справочнике», пример поиска («конь»), вход, заглушка режима техработ, страница 404.
- Панель управления, как её видит `admin`: список предметов (общий и по каждому разделу — в нём авторский порядок), редактор каждого предмета и нового предмета, рубрикатор с формой каждого раздела и нового раздела, «Пользователи», «Журнал».
- Черновик (ЛФЗ-1071) и скрытый раздел «Книги и каталоги» отрендерены так, как их видит администратор: гостю они в движке не видны, ссылки на них есть только в панели.
- В подвале каждой страницы — «Статическая демонстрационная версия: контент условный.»

Сервера у статики нет, его заменяет `demo/js/demo.js` (подключается на каждой странице перед скриптом движка):

- **вход:** открытие любой страницы панели или отправка формы входа «входит» (флаг в `localStorage`), ссылка «выход» в подвале «выходит»; на публичных страницах при входе видны подвал администратора и кнопки «Редактировать»;
- **режим техработ:** переключатель на странице «Пользователи» запоминается в `localStorage`; гость тогда попадает на `maintenance.html`, администратор видит жёлтую полосу под шапкой;
- **формы и фоновые сохранения** (перетаскивание, загрузка фото) получают ответ «как от сервера» и сообщение, что демо ничего не сохраняет; фильтр «Раздел» в списке предметов открывает отрендеренный список раздела; форма поиска открывает `search.html`; смена сортировки каталога показывает сообщение (сортирует сервер).

## Как обновить демо-версию

Делается по просьбе владельца репозитория, на текущем коммите. Все команды — в отдельной копии, рабочий сайт и песочница не задействуются.

### 1. Чистая установка с этой базой

1. Клон репозитория в отдельный каталог, `composer install --no-dev`.
2. Отдельная пустая база MariaDB (например, `estables_demo`), загрузить в неё `estables-demo.sql`.
3. `config/config.php` из шаблона: секрет, доступ к базе, `app.timezone` = `Europe/Moscow`, капча `stub`. `app.base_url` не важен (канонические адреса из демо удаляются).
4. Скопировать `demo/media/originals/` в `public/media/originals/` установки.
5. `bin/estables migrate` (если движок новее дампа), затем `bin/estables media:warm` — уменьшенные копии.

### 2. Контент

Если новой версии движка нужен новый контент (новая сущность, новая страница), добавить его в базу через панель или прямо в базе, условный и в духе существующего: фарфоровые и прочие лошади, выдуманные номера и описания. Новые фото — такие же заглушки (силуэт лошади на градиенте, JPEG до 1600 px). Если нужны данные для новых таблиц журнала, сессий и т. п. — тоже выдуманные: IP из документационных диапазонов (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24).

### 3. Рендер

Страницы рендерятся самим движком (ядро вызывается из PHP напрямую, как в интеграционных тестах), двумя «браузерами»:

- **гость** — без cookie;
- **администратор** — вход `admin` / `demo-password-2026`, User-Agent Firefox на Linux, IP `203.0.113.24` (так в «Пользователях» текущая сессия выглядит как «Firefox, Linux»).

Обход начинается с `/`, `/about/`, `/login/`, `/search/?q=конь`, `/admin/`, `/admin/rubrics/`, `/admin/users/`, `/admin/audit/`, `/admin/items/new/`, `/admin/rubrics/?new=1` и `/admin/?rubric=<id>` для каждого раздела, дальше — по всем внутренним ссылкам (`href` и `data-es-href`), пока не кончатся новые файлы. Адреса `/admin…` рендерит администратор, остальные — гость; если гость получил 404 (черновик, скрытый раздел), страницу рендерит администратор.

Адреса движка и файлы демо:

| Адрес движка | Файл |
|---|---|
| `/`, `/catalog/` | `index.html` |
| `/about/`, `/login/` | `about.html`, `login.html` |
| `/search/?q=…` (любой запрос) | `search.html` — отрендерен для `q=конь` |
| `/catalog/a/b/c/` | `catalog-a-b-c.html`; `?decade=1960` → `…-d1960.html`; `?page=2` → `…-p2.html`; `?sort` отбрасывается |
| `/item/<slug>/` | `item-<slug>.html` |
| `/admin/`, `/admin/?rubric=N` | `admin-items.html`, `admin-items-rN.html` (остальные параметры отбрасываются) |
| `/admin/items/N/`, `/admin/items/new/…` | `admin-item-N.html`, `admin-item-new.html` |
| `/admin/rubrics/`, `?id=N`, `?new=1…` | `admin-rubrics.html`, `admin-rubric-N.html`, `admin-rubric-new.html` |
| `/admin/users/`, `/admin/audit/…` | `admin-users.html`, `admin-audit.html` |
| `/assets/<путь>?v=…` | `assets/<путь>` |
| `/media/<путь>` | `media/<путь>` |
| `/download/<sha>/<имя>.<ext>` | `media/originals/<первые 2 символа sha>/<sha>.<ext>` и атрибут `download="<имя>.<ext>"` |
| любой другой `/…` (адреса POST и AJAX: `/logout/`, `/admin/items/bulk/` и т. п.) | `#` |

Отдельно:

- `maintenance.html` — главная глазами гостя при включённом режиме техработ (включить, отрендерить, выключить);
- `404.html` — любой несуществующий адрес глазами гостя (GitHub Pages отдаёт этот файл на неизвестные адреса).

Переделки в каждом файле после замены адресов (атрибуты `href`, `src`, `srcset`, `action`, `data-*`):

1. Удалить `<link rel="canonical">`, `<meta property="og:…">`, `<meta name="twitter:…">`.
2. Перед `<script src="assets/js/estables.js">` вставить `<meta name="es-demo-area" content="…">` (`admin` — страницы панели, `login` — вход, `stub` — заглушка, `public` — остальные) и `<script src="js/demo.js"></script>`.
3. Подвал:
   - у гостя после ссылки «Вход администратора» добавить скрытый вариант администратора: `<span data-es-auth="admin" hidden>Вы — администратор (<a href="admin-items.html">панель управления</a> | <a href="index.html" data-es-logout>выход</a>)</span>`;
   - у администратора кнопку «выход» заменить такой же ссылкой `data-es-logout`, форму `es-logout` удалить;
   - перед ссылкой «Исходный код» вставить «Статическая демонстрационная версия: контент условный.».
4. Сразу после `</header>` — скрытая полоса режима техработ, как в `templates/layouts/site.php`, с атрибутами `data-es-demo-maintenance hidden` и ссылкой на `admin-users.html#maintenanceTitle`.
5. На страницах предметов после номера (`<span class="es-catno">` над заголовком) — кнопка `<a class="btn btn-sm btn-outline-secondary" href="admin-item-N.html" data-es-auth="admin" hidden><i class="bi bi-pencil me-1" aria-hidden="true"></i>Редактировать</a>`.

### 4. Сборка `demo/`

1. Удалить из `demo/` всё, кроме `js/demo.js`.
2. Положить отрендеренные HTML-файлы.
3. Скопировать `public/assets/` установки в `demo/assets/` целиком.
4. Скопировать из `public/media/` установки только файлы, на которые ссылаются страницы.
5. Если движок поменял что-то, что имитирует `demo.js` (формы, AJAX, вход, режим техработ), поправить `demo.js`.

### 5. Проверка

- В HTML не осталось атрибутов со значением на `/` и ссылок на `https://example.org`; у каждой локальной ссылки есть файл.
- Отдать `demo/` статическим сервером из подкаталога (как на GitHub Pages: `https://<пользователь>.github.io/estables/`) и пройти в браузере без ошибок в консоли: каталог → раздел → десятилетие → предмет (миниатюры, просмотр во весь экран, «Скачать оригинал») → поиск → вход → список предметов → фильтр по разделу → редактор → рубрикатор → журнал → «Пользователи» → режим техработ → выход (заглушка) → вход → выключить режим. Плюс ширина телефона.

### 6. Если контент менялся — новый дамп

Перед дампом убрать то, что оставил рендер: сессию и запись входа администратора с IP `203.0.113.24` за день рендера, строки таблицы `settings`. Дамп — с `--skip-extended-insert --skip-dump-date`, чтобы изменения читались в diff:

```sh
mariadb-dump --single-transaction --skip-extended-insert --skip-dump-date \
    --default-character-set=utf8mb4 --no-tablespaces estables_demo > tools/demo-build/estables-demo.sql
```
