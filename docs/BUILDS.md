# Сборки движка

Каждая сборка разворачивается в LNMP-песочнице по [SANDBOX.md](SANDBOX.md) и проверяется в браузере. Эталон оформления и поведения — статическое демо в `demo/` на коммите `0a21c112`.

## Сборка 1. Установка

**Схема БД:** версия 2 (шаг 0 — `schema_meta`, шаг 1 — `users`).

### Что работает

- Страница «Установка eStables», пока нет `config/config.php`, и страница со списком ошибок, если конфигурация заполнена неверно.
- Самодеплой: при первом запросе с рабочей конфигурацией проверяется сервер, затем создаётся схема базы. Повторные запросы в базу за версией схемы не ходят (кеш в `var/cache/schema.version`).
- Самообновление: если код новее базы, схема обновляется сама, перед этим делается резервная копия. Пока идёт обновление, остальные запросы получают «Идёт обновление» (503). Если база новее кода, сайт не запускается и объясняет почему.
- Мастер первого администратора по токену из `var/install.token`, с проверкой полей. После создания администратора форма закрывается (404).
- Пустой каталог в оформлении демо: шапка, боковая колонка рубрикатора, хлебные крошки, футер, переключатель темы.
- Страницы ошибок 404, 500 и служебные страницы в стиле сайта.
- Заголовки безопасности, включая строгий Content-Security-Policy без внешних доменов: вся статика лежит локально.
- Консоль: `bin/estables check | migrate | status | create-admin`.

### Как проверить в браузере

1. Без `config/config.php` открыть сайт — инструкция по установке.
2. Создать конфигурацию, обновить страницу — откроется форма «Первый администратор»; в базе появятся таблицы `schema_meta` и `users`.
3. Отправить форму с неверным токеном и коротким паролем — сообщения у полей, введённые значения (кроме паролей) сохраняются.
4. Отправить с токеном из `var/install.token` — «Установка завершена», файл токена удалён.
5. Главная — пустой каталог; `/setup/` — 404; любой несуществующий адрес — 404.
6. Переключить тему на тёмную и обновить страницу — тема сохраняется.
7. Обновление схемы: `UPDATE schema_meta SET value='1' WHERE name='version'`, удалить `var/cache/schema.version`, открыть сайт — схема снова версии 2, в `var/backups/` появился дамп.

### Отличия от демо

- В меню только «Каталог»: пункты «Новые поступления», «Производители», «О справочнике» были в демо заглушками и в план не входили.
- Поля поиска в шапке пока нет — поиск появится в сборке 4.
- В футере нет ссылки «Вход администратора» — вход появится в сборке 2.
- Каталог пуст: рубрикатор — сборка 3, предметы — сборка 4.
- Страницы мастера установки и служебные страницы в демо отсутствуют; их стили собраны в разделе 7 `public/assets/css/estables.css`, всё остальное в этом файле совпадает с `demo/css/estables.css`.

## Сборка 2. Вход и пользователи

**Схема БД:** версия 4. Шаг 2 добавляет `sessions`, шаг 3 — `login_attempts`. Сайт сборки 1 обновляется сам при первом запросе, перед этим делается резервная копия.

**Новые настройки** (разделы `session`, `login`, `captcha` в `config/config.template.php`) необязательны: без них действуют значения по умолчанию, капча — заглушка.

### Что работает

- Вход по адресу `/login/`, ссылка «Вход администратора» в подвале. Ошибка не уточняет, что неверно — логин или пароль. Пароль в Argon2id, старые хеши пересчитываются при входе.
- «Запомнить меня»:
  - без отметки cookie живёт до закрытия браузера, а сервер завершает сессию после 12 часов бездействия;
  - с отметкой срок 30 дней, он продлевается при заходах (в базе и в cookie, не чаще раза в 5 минут).
- Сессии в БД:
  - в cookie только случайный идентификатор, в базе — его SHA-256;
  - идентификатор меняется при входе и раз в сутки; старый ещё минуту принимается для параллельных запросов;
  - неизвестная или истёкшая cookie не оживает, а удаляется.
- Выход из подвала — POST с CSRF-токеном: удаляет сессию на сервере и cookie.
- Подвал от сервера: гость видит «Вход администратора», администратор — «Вы — администратор (панель управления | выход)» на всех страницах, включая 404.
- Защита от перебора:
  - 5 неудач для логина или 20 с одного IP за 15 минут блокируют форму, сообщение говорит, на сколько минут;
  - каждая неудача пишется в `var/log/estables.log`.
- Капча: `stub` (галочка, как в демо; без неё вход не пройдёт) и `turnstile` (Cloudflare Turnstile с проверкой ответа на сервере; CSP страницы входа расширяется только для `challenges.cloudflare.com`).
- Админка закрыта: любой адрес `/admin/…` без входа ведёт на форму входа и после входа возвращает обратно. Все POST в админке проверяют CSRF-токен сессии; без него — 403.
- Оболочка админки как в демо: шапка «eStables администрирование», меню «Предметы / Рубрикатор / Пользователи», «Открыть сайт», переключатель темы. «Предметы» и «Рубрикатор» — заглушки до сборок 4 и 3.
- Страница «Пользователи»:
  - список администраторов: последний вход, число сессий, статус;
  - добавление; ошибки показываются в том же окне, оно открывается снова;
  - смена пароля, для своего — с вводом текущего, с отметкой «завершить сессии»;
  - блокировка и разблокировка, кроме самого себя; блокировка сразу завершает сессии;
  - «Завершить сессии» любого администратора; для себя это выход везде;
  - «Мои активные сессии»: браузер и система, IP, вход, активность, срок; завершение одной или всех, кроме текущей.
- Консоль: `bin/estables passwd <логин>` (сменить пароль и завершить сессии), `bin/estables unlock <логин>` (снять блокировку после неудачных попыток).

### Как проверить в браузере

1. Обновить песочницу до сборки 2 и открыть сайт. В базе версия схемы 4, появились таблицы `sessions` и `login_attempts`, в `var/backups/` — дамп `…-before-v4`.
2. Главная: в подвале «Вход администратора». В инструментах разработчика у гостя нет cookie.
3. Открыть `/admin/users/` — переадресация на вход. Ввести неверный пароль — «Неверный логин или пароль», логин в поле сохранился. Снять галочку капчи — «Подтвердите, что вы человек».
4. Войти без «Запомнить меня» — откроется «Пользователи». Cookie `es_session`: HttpOnly, SameSite=Lax, срок «Session». Закрыть браузер целиком, открыть `/admin/` — снова форма входа (если браузер не настроен восстанавливать вкладки: тогда он сохраняет и такие cookie, и сессию закончит серверный таймаут в 12 часов).
5. Войти с отметкой в другом браузере (или в окне инкогнито). У cookie срок через 30 дней. В первом браузере в «Моих активных сессиях» две строки, у текущей — «это устройство».
6. «Завершить» у второй сессии, затем обновить страницу во втором браузере — снова форма входа.
7. «Добавить администратора» с занятым логином и коротким паролем — окно откроется снова с сообщениями у полей. Исправить — «Администратор добавлен».
8. Войти новым администратором во втором браузере. В первом заблокировать его (подтвердить) — во втором браузере сессия закончилась, повторный вход: «Учётная запись заблокирована». Разблокировать.
9. Сменить свой пароль с неверным текущим — ошибка в окне. Сменить с верным и отметкой — остальные мои сессии завершены, текущая осталась.
10. Открыть главную — в подвале «Вы — администратор (панель управления | выход)». «выход» — снова гость.
11. Шесть раз ввести неверный пароль — «Слишком много неудачных попыток. Попробуйте снова через 15 минут.». `runuser -u www-data -- php bin/estables unlock <логин>` — вход снова работает.
12. Сравнить `/login/` и `/admin/users/` с `demo/login.html` и `demo/admin-users.html` в светлой и тёмной теме и на ширине телефона.
13. Turnstile без своего аккаунта: тестовые ключи Cloudflare в `config/config.php` — `'captcha' => ['provider' => 'turnstile', 'site_key' => '1x00000000000000000000AA', 'secret_key' => '1x0000000000000000000000000000000AA']` (всегда пропускают). На форме входа вместо галочки появится виджет Cloudflare, вход работает. С ключом `2x0000000000000000000000000000000AA` (всегда отказ) — «Подтвердите, что вы человек». Вернуть `stub`.

### Отличия от демо

- Под капчей нет подписи «В демо-версии это условное место для модуля капчи»; галочка-заглушка — обязательное поле формы. При `turnstile` на её месте виджет Cloudflare.
- Окно смены пароля своё у каждого администратора. В заголовке — логин, если пароль чужой. Для своего пароля есть поле «Текущий пароль», а отметка называется «Завершить остальные мои сессии».
- Блокировка и «Завершить сессии» спрашивают подтверждение. После действий сверху появляется сообщение о результате.
- «Завершить все, кроме этой» неактивна, когда других сессий нет. «Завершить сессии» неактивна у администратора без сессий.
- «только что» в колонке «Активность» показывается только у текущего устройства, у остальных — время последней активности (обновляется раз в 5 минут).
- «выход» в подвале — кнопка отправки формы, оформленная как ссылка: выход меняет состояние и потому идёт через POST.
- Пока нет предметов и разделов, «Предметы» и «Рубрикатор» в админке — страницы-заглушки.
- На странице входа ставится короткоживущая cookie формы `es_form` (CSRF до входа, 2 часа). После входа она удаляется.

## Сборка 2.1. Показ пароля и «О справочнике»

**Схема БД:** без изменений (версия 4).

### Что работает

- Кнопка «глаз» у поля пароля во всех формах, где пароль задаётся: мастер первого администратора, «Добавить администратора», «Сменить пароль» (свой и чужой).
- Пока пароль показан, поле подтверждения скрыто и отключено. Отключённое поле браузер не отправляет, и сервер не сравнивает пароли. Если пароль снова скрыть, поле подтверждения вернётся, а сравнение снова заработает. Без JavaScript поле подтверждения есть всегда.
- В меню сайта пункт «О справочнике» (`/about/`). Текст пока в шаблоне `templates/pages/about.php`; правка из админки записана в план на будущее.
- Меню на страницах ошибок ведёт туда же, куда и на остальных страницах.

### Как проверить в браузере

1. «Пользователи» → «Добавить администратора»: нажать «глаз» — пароль виден, поля «Пароль ещё раз» нет. Добавить администратора без подтверждения — «Администратор добавлен».
2. Снова открыть окно, нажать «глаз» дважды — поле подтверждения вернулось. Ввести разные пароли — «Пароли не совпадают».
3. То же в «Сменить пароль» у себя (поле «Текущий пароль» остаётся) и у коллеги.
4. Мастер первого администратора (на чистой базе): «глаз» скрывает «Пароль ещё раз», установка проходит без него.
5. Меню «Каталог / О справочнике»: страница открывается, пункт подсвечен, ссылки открываются в новой вкладке. На 404 пункт меню ведёт на `/about/`.

### Отличия от демо

- В демо у полей пароля в окнах «Добавить администратора» и «Сменить пароль» нет «глаза», и поле подтверждения не скрывается.
- В меню нет пунктов «Новые поступления» и «Производители». Страницы «О справочнике» в демо нет: там пункт меню ведёт на `#`.

## Сборка 3. Рубрикатор

**Схема БД:** версия 6. Шаг 4 добавляет `rubrics`, шаг 5 — `slug_history`.

### Что работает

- Админка «Рубрикатор» (`/admin/rubrics/`), как в демо: дерево разделов слева, форма выбранного раздела справа.
  - Добавление: кнопка «Добавить раздел» или «+» у раздела в дереве (подраздел).
  - Правка:
    - название;
    - заголовок страницы;
    - родительский раздел;
    - адрес — латиница, цифры, дефисы; если пусто, адрес получается из названия транслитерацией, а при совпадении с соседним разделом к нему добавляется «-2»;
    - описание — пустая строка начинает абзац;
    - видимость на сайте.
  - Перестановка в дереве:
    - мышью, пальцем или клавиатурой (на значке перетаскивания: ↑ ↓ меняют порядок, ← → — вложенность);
    - каждое перемещение сразу сохраняется на сервере;
    - если сервер отказал (например, у соседа уже есть такой адрес), страница показывает причину и перезагружает дерево.
  - Удаление через окно подтверждения. Раздел с подразделами удалить нельзя: сначала их нужно перенести или удалить.
- Адреса разделов вида `/catalog/figurki/farfor/lfz/`. При смене адреса или переносе старые адреса раздела и всех его подразделов отвечают 301 на новые.
- Публичная часть:
  - рубрикатор в боковой колонке, как в демо: путь к текущему разделу выделен и раскрыт, остальные ветки свёрнуты;
  - на телефоне рубрикатор открывается кнопкой «Рубрикатор» и выезжает слева;
  - корень каталога показывает разделы верхнего уровня карточками;
  - страница раздела: хлебные крошки, заголовок и описание, подразделы карточками.
- Скрытый раздел вместе со всем поддеревом:
  - гостю отвечает 404 и не виден в рубрикаторе;
  - администратор видит его с пометкой «скрыт», страница закрыта от поисковиков.
- Дерево читается одним запросом и кешируется в `var/cache/rubrics.ser`; кеш сбрасывается любым изменением.

### Как проверить в браузере

1. Обновить песочницу. Версия схемы 6, появились таблицы `rubrics` и `slug_history`.
2. «Рубрикатор» в админке: пустое дерево и форма «Новый раздел». Добавить «Фигурки» без адреса — адрес `figurki`. Кнопкой «+» у «Фигурки» добавить «Фарфор», в нём «Ленинградский завод» с адресом `lfz`, заголовком и описанием.
3. Отправить форму без названия и с адресом «Плохой адрес» — сообщения у полей.
4. Открыть сайт: «Фигурки» карточкой на главной; `/catalog/figurki/farfor/lfz/` — крошки «Каталог / Фигурки / Фарфор / Ленинградский завод», путь в рубрикаторе выделен. Сравнить с `demo/index.html`.
5. Перетащить разделы мышью (выше, ниже, внутрь другого) и клавиатурой (Tab до значка ⠿, стрелки). Обновить страницу — порядок сохранился. На сайте рубрикатор в том же порядке.
6. Сменить адрес «Фигурки» на `figury` — `/catalog/figurki/farfor/lfz/` отвечает 301 на `/catalog/figury/farfor/lfz/`.
7. Выключить «Показывать раздел на сайте» у «Фарфор» — в другом браузере (гость) он и его подразделы пропали, адрес отвечает 404; у администратора они с пометкой и предупреждением на странице.
8. Удалить «Фарфор» — окно говорит, что сначала нужно убрать подразделы, кнопка неактивна. Удалить лист — «Раздел удалён», его адрес отвечает 404.
9. Телефон: кнопка «Рубрикатор» на странице раздела открывает дерево.

### Отличия от демо

- Счётчики предметов пока нули, цифр «Моделей / Вариантов / Годы выпуска», фильтра по десятилетиям, сортировки и списка предметов нет — это сборка 4.
- В форме раздела нет поля «Обложка раздела» — обложки появятся с фотографиями в сборке 5.
- Подразделы на странице раздела и разделы на главной показаны карточками в стиле карточек предметов; в демо такого блока нет. Пока обложек нет, в карточке пустая подложка со значком.
- Кнопка «Рубрикатор» для телефона стоит над карточками; в демо она в панели сортировки, которой пока нет.
- Окно удаления раздела пока без выбора «перенести или удалить предметы» — предметов ещё нет.
- Правая колонка админки без выбранного раздела показывает подсказку «Раздел не выбран»; в демо всегда открыт раздел.
- У поля адреса есть подсказка о правилах и о переадресации старого адреса.

## Сборка 4. Предметы

**Схема БД:** версия 11. Шаги 6–10 добавляют `items`, `item_rubrics`, `attribute_names`, `item_attributes`, `item_variants`.

### Что работает

- **Редактор предмета** (`/admin/items/new/`, `/admin/items/<id>/`), как в демо:
  - номер в каталоге, уникальный без учёта регистра; пустой номер заполняется при сохранении (пока номером записи: `00042`);
  - название, краткое и полное описание;
  - годы выпуска «с — по»: этих полей в демо нет, на них опираются фильтр по десятилетиям, сортировка по году и цифры раздела;
  - разделы как теги: первый добавленный — главный, можно переназначить, последний убрать нельзя; в новом разделе предмет встаёт в начало авторского порядка;
  - характеристики с подсказками названий из уже введённых; варианты; строки переставляются перетаскиванием;
  - статус «опубликован / черновик», даты создания и изменения;
  - удаление с подтверждением.
- Адрес предмета `/item/lfz-1042/` получается из номера. При смене номера старый адрес отвечает 301 на новый.
- **Список предметов** (`/admin/`):
  - поиск по названию и номеру, фильтры по разделу и статусу, сортировка (по изменению, номеру, названию);
  - страницы по 50 строк;
  - при выбранном разделе — его авторский порядок: перетаскивание строк, стрелки в строке, ↑ ↓ на значке; каждое перемещение сразу сохраняется;
  - массовые действия над отмеченными:
    - добавить в раздел (в начало) или убрать из раздела (последний раздел предмета не снимается, главный переходит к следующему);
    - в начало, в конец или на позицию (подряд, в нынешнем взаимном порядке);
    - опубликовать, снять с публикации, удалить.
- **Удаление раздела с предметами**:
  - у предметов, которые есть и в других разделах, связь просто снимается;
  - для остальных нужно выбрать: перенести в другой раздел (в начало) или удалить.

- **Страница предмета**:
  - крошки от главного раздела;
  - номер, название, краткое описание;
  - характеристики: годы выпуска, свободные характеристики, «Также в разделах»;
  - варианты, полное описание;
  - «Соседние модели» (предыдущая и следующая в авторском порядке главного раздела), «Из той же серии» (четыре следующих предмета главного раздела);
  - администратору — кнопка «Редактировать».
- **Видимость.** Черновик и предмет, у которого все разделы скрыты, гостю отвечают 404 и нигде не показываются. Администратор видит их с предупреждением.
- **Поиск** из шапки сайта (`/search/?q=`):
  - ищет по номеру, названию, описаниям, характеристикам и вариантам среди опубликованных предметов видимых разделов;

## Сборка 5. Фотографии

**Схема БД:** версия 14. Шаги 11–13 добавляют `images`, `item_photos` и обложку раздела `rubrics.cover_image`.

**Сервер:** обязателен `php8.4-imagick`, желателен `jpegtran` (пакет `libjpeg-turbo-progs`). В конфигурации nginx новый блок `location ^~ /media/` — её нужно скопировать заново.

### Что работает

- **Загрузка в редакторе предмета**:
  - кнопка или перетаскивание файлов на зону «Добавить фото», можно несколько сразу; файлы уходят по одному, плитки появляются по мере загрузки;
  - JPEG, PNG и GIF (в том числе анимированный) сохраняются в своём формате, WebP, AVIF, BMP и TIFF — преобразуются в JPEG, прозрачность заливается белым; HEIC и не-картинки отклоняются с сообщением;
  - метаданные убираются: EXIF (с геометкой и моделью камеры), XMP, комментарии, текстовые блоки PNG. Цветовой профиль остаётся. Поворот из EXIF применяется к самой картинке, у JPEG — без пересжатия (`jpegtran`);
  - одно и то же фото дважды к предмету не добавляется; одинаковые файлы у разных предметов хранятся один раз.
- **Порядок, подписи, обложка**: плитки перетаскиваются, звёздочка ставит фото первым — оно обложка; подпись у каждого фото; корзина убирает фото. Всё это сохраняется кнопкой «Сохранить».
- **Страница предмета**: большое фото, миниатюры (если фото больше одного), «Скачать оригинал» с форматом, размером и весом файла. Клик по фото — полноэкранный просмотр (GLightbox) с листанием и ссылкой на оригинал. Скрипт и стили просмотрщика загружаются только на страницах предметов с фото.
- **Обложки**: в карточках предметов — первое фото; в карточках разделов — своя обложка раздела, а без неё — первое фото первого опубликованного предмета, затем обложка первого подраздела. Свою обложку раздела можно загрузить и убрать в форме раздела. В списке админки — миниатюра и число фото.
- **Размеры**: в карточках копия 400 px по длинной стороне (на экранах высокой плотности — 1600), на странице предмета — 1600. Оригинал до 2560 px показывается сам, без копии. Копии делаются при первом запросе, дальше их отдаёт nginx с кешем на год.
- **Скачивание**: `/download/<хеш>/lfz-1042-2.jpg` — файл с понятным именем, отдаёт nginx.
- **Консоль**: `bin/estables gc` удаляет фото, которые никому не нужны больше суток, и файлы без записи в базе, а также истёкшие сессии и старые попытки входа; `bin/estables media:warm` делает все копии заранее.

### Как проверить в браузере

1. Обновить песочницу и заново скопировать конфигурацию nginx (SANDBOX.md, п. 4). `bin/estables check` — строки imagick и jpegtran «ok». Версия схемы 14.
2. Открыть предмет в редакторе, перетащить на зону несколько файлов: снимок с телефона (портретный), PNG, анимированный GIF, WebP. Плитки появляются одна за другой, первая помечена «Обложка».
3. Загрузить тот же снимок ещё раз — сообщение «Это фото уже есть у предмета». Загрузить текстовый файл с расширением `.jpg` — «Это не изображение…».
4. Нажать звёздочку у второго фото, вписать подпись, убрать одно фото корзиной, перетащить плитки. Обновить страницу без сохранения — всё как было; сохранить — изменения на месте.
5. Открыть предмет на сайте: портретный снимок стоит правильно, миниатюры переключают большое фото и «Скачать оригинал». Клик по фото — просмотр во весь экран, стрелки листают, Esc закрывает.
6. Скачать оригинал и открыть в просмотрщике метаданных (например, `exiftool файл.jpg`): нет модели камеры, геометки и даты съёмки.
7. На странице раздела и на главной — обложки в карточках предметов и разделов. В форме раздела загрузить свою обложку — на главной она заменит заимствованную; «Убрать обложку» возвращает прежнюю.
8. В консоли: `runuser -u www-data -- php bin/estables media:warm` и `… gc` (убранное в п. 4 фото удалится не раньше чем через сутки).

### Отличия от демо

- У нового предмета фото можно добавить только после первого сохранения: до него зона загрузки заменена пояснением.
- Загруженное фото сохраняется сразу, а порядок, подписи и удаление — кнопкой «Сохранить». Под зоной загрузки об этом есть строка.
- На сайте подпись к фото служит его описанием (alt и подпись в полноэкранном просмотре); без подписи — название предмета и номер фото.
- «Скачать оригинал» ведёт на `/download/…`: имя файла задаёт сервер, атрибута `download` у ссылки нет.
- На странице предмета с фото политика безопасности разрешает атрибуты `style` (`style-src-attr 'unsafe-inline'`): ими GLightbox задаёт размеры слайда. Элементы `<style>` и чужие стили по-прежнему запрещены.

### Что работает

  - `robots.txt` закрывает админку, вход, поиск и скачивание и указывает на карту сайта;

- **Журнал сервера**: время записано с поясом, логин в строках неудачного входа экранирован — подделать строку для fail2ban набранным логином нельзя.
- **Обслуживание**:
  - `bin/estables backup` — ежесуточный дамп базы; хранится своё число копий (`backup.keep_daily`), копии перед обновлением схемы ими не вытесняются;

### Как проверить в браузере

1. Обновить песочницу, заново скопировать конфигурацию nginx (SANDBOX.md, п. 4). Версия схемы 15.

8. Таймеры и fail2ban в песочнице ставить не обязательно. Проверить фильтр на журнале: после пары неудачных входов `fail2ban-regex var/log/estables.log deploy/fail2ban/filter.d/estables.conf` находит адрес.

- Неудачные попытки входа в «Журнал» не попадают: их пишет только `var/log/estables.log` (для fail2ban). Иначе боты могли бы засорить журнал.

## Сборка 7.1. Режим техработ

**Схема БД:** версия 16. Шаг 15 добавляет таблицу `settings` для настроек, которые меняются в панели управления.

### Что работает

- Внизу страницы «Пользователи», под сессиями, — переключатель «Сайт закрыт для посетителей». Срабатывает сразу при щелчке (без JavaScript — кнопкой «Применить»), включение и выключение записываются в «Журнал».
- Пока режим включён, гость на любой странице сайта видит заглушку «Ведутся технические работы», оформленную как «О справочнике»; в шапке только эмблема и переключатель темы — без меню и поиска. Ответ — 503 с `Retry-After: 3600` и `noindex`, чтобы поисковики не выбросили страницы из индекса. Открыты только вход и `robots.txt`; ссылка «Вход администратора» в подвале на месте.
- Вошедший администратор видит сайт целиком; под шапкой каждой страницы — жёлтая полоса «Включён режим техработ» со ссылкой, где его выключить.

### Как проверить в браузере

1. Обновить песочницу (версия схемы 16).
2. «Пользователи» → внизу «Режим техработ» → включить переключатель: сообщение «Режим техработ включён», под шапкой — жёлтая полоса.
3. В другом браузере (или приватном окне) открыть главную, раздел, предмет, поиск — везде заглушка. Войти через «Вход администратора» в подвале — сайт виден целиком.
4. Выключить переключатель — гостям снова виден сайт. В «Журнале» — обе записи (фильтр «Что» → «Сайт»).

### Отличия от демо

- В демо нет ни переключателя, ни заглушки; заглушка сделана по образцу «О справочнике», переключатель — как «Показывать раздел на сайте» в рубрикаторе.
